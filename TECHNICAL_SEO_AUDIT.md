# Technical SEO audit — Star Cleaning Kuwait

Audit date: 19 November 2026. This report records the findings **before changes for this technical audit**. The published website and the existing, unpublished source were inspected separately. Earlier bilingual SEO improvements were already present in the source and were not treated as new implementation work.

## Scope and method

Checked the published homepage, sitemap, robots.txt, intended Arabic/service URLs, missing-page responses, HTTPS redirects, certificate, response headers, rendered resources and structured data. Crawled the source through a local Netlify preview: 12 canonical pages and 218 internal links. Browser layout checks covered all 12 pages at 390px and 1440px, with homepage/representative service checks at 320, 360, 760, 768 and 1024px: 44 layout cases. An initial preview run was discarded because stale generated function output referenced an unavailable compiled stylesheet; the generated output was isolated and the correctly styled source was checked again.

Lighthouse 13.6.0 measured the published homepage on 19 November 2026 at 21:32 UTC. Mobile used Lighthouse's simulated mobile profile. Desktop used a 1350×940 viewport, 40ms RTT, 10Mbps throughput and no CPU slowdown. Each profile was measured once; these are lab snapshots, not a field Core Web Vitals verdict or a guaranteed repeatable score. No production build, deployment, Search Console account action or external account change was performed.

## Verified changes to implement

1. **Image delivery (medium):** cap requested image widths and srcset descriptors at actual original widths, deduplicate capped candidates, and add 640/800px hero options. Keep the same image files, quality, layout and CSS cropping.
2. **Font discovery (medium):** move language-specific font preloads out of the shared shell. English should prioritize the fonts it renders; Arabic should prioritize Noto Sans Arabic and avoid the unused Cormorant Garamond preload on service pages. Arabic homepage statistics still use Cormorant Garamond numerals, which must be retained. Keep all font files and font-display behavior.
3. **Accessible names (low, supplemental mobile usability):** Lighthouse verifies visible-label/accessibility-name mismatches on brand links, language controls and decorative card numbers. Correct the invisible labels/semantics without changing visible design or copy.

## Findings that do not justify source changes

Lighthouse flags approximately 51KiB of unused JavaScript on the live homepage, but TBT is zero and the report alone does not establish which interactive or framework code is safe to remove. Existing route splitting is retained. A cache warning concerns an approximately 11KiB platform-injected script with a 60-second TTL; this is not an application asset and is not addressed with broad caching rules. The inspected live HTML/CSS and scripts are compressed in the browser network trace; an uncompressed Python request is not evidence of missing compression.

Lighthouse also flags color contrast. Changing the palette would affect the explicitly protected design, so no color changes are included in this technical SEO pass. This remains an accessibility follow-up, with a separate approved visual scope if desired. The Lighthouse SEO score of 100 describes its automated checks on the current English homepage; it does not establish Arabic indexing, schema rich-result eligibility, ranking or field Core Web Vitals.
